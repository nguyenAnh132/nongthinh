================================================================================
PROFILE SERVICE - API ENDPOINTS
================================================================================

Base URL (qua API Gateway):  http://localhost:8888/api/v1/profile
Base URL (trực tiếp service): http://localhost:9092/profile
Context path (dev): /profile
Port (dev): 9092

--------------------------------------------------------------------------------
FOLLOW (ROLE_FARMER / ROLE_BRAND)
--------------------------------------------------------------------------------
GET    /users/{userId}/follow-profile
       result: {userId, displayName, avatarUrl, role, followerCount, followingCount, following}
PUT    /users/{userId}/follow          (không cần body; idempotent)
DELETE /users/{userId}/follow          (idempotent)
GET    /users/{userId}/followers?page=0&size=20
GET    /users/{userId}/following?page=0&size=20
       result: {items: [FollowProfile], page, size, hasNext}; size: 1..100.
GET    /users/following-status?userIds=<uuid>,<uuid>
       result: danh sách userId đang theo dõi trong nhóm được hỏi (tối đa 100).

Quan hệ lưu trong PostgreSQL của profile-service (migration V9).
Chỉ hồ sơ ACTIVE được follow và xuất hiện trong danh sách/bộ đếm công khai.
Không cho tự follow. Người thao tác lấy từ JWT, không lấy từ request body.
Thông báo NEW_FOLLOWER và FOLLOWED_USER_POST đi qua transactional outbox.
Post-service phát post.published khi tạo/xuất bản bài công khai.
Profile-service nhận KAFKA_TOPIC_POST_ENGAGEMENT (mặc định post.engagement.v1),
gửi KAFKA_TOPIC_PROFILE_NOTIFICATIONS (mặc định profile.notifications.v1) cho notification-service.
Sự kiện lỗi sau retry đi vào topic .DLT; cần cấu hình broker/ACL cho các topic này.
Người follow sau thời điểm đăng bài không nhận thông báo về bài cũ.
Không triển khai gợi ý kết nối.

--------------------------------------------------------------------------------
HEADERS
--------------------------------------------------------------------------------
Authorization: Bearer <access_token>
Content-Type: application/json    (chỉ bắt buộc khi có request body)

--------------------------------------------------------------------------------
COOKIES
--------------------------------------------------------------------------------
Không bắt buộc. Service dùng OAuth2 Resource Server (JWT qua header Authorization).

--------------------------------------------------------------------------------
RESPONSE FORMAT
--------------------------------------------------------------------------------
Tất cả endpoint bọc trong ApiResponse:
{
  "code": "string | null",
  "message": "string",
  "result": <T> | null
}

HTTP status:
- GET thành công     : 200 OK
- POST tạo mới       : 201 Created
- PATCH cập nhật     : 200 OK

================================================================================
1. FARMER PROFILES  (/farmer-profiles)
================================================================================

--- GET /farmer-profiles/me ---
Mô tả   : Lấy profile nông dân của user hiện tại
Auth    : ROLE_FARMER
Response: ApiResponse<FarmerProfileView>

--- POST /farmer-profiles/me ---
Mô tả   : Tạo profile nông dân cho user hiện tại
Auth    : ROLE_FARMER
Body    : MyFarmerProfileCreationRequest
Response: 201 Created, ApiResponse<Void>

--- PATCH /farmer-profiles/me ---
Mô tả   : Cập nhật thông tin profile nông dân
Auth    : ROLE_FARMER
Body    : MyFarmerProfileUpdateRequest
Response: ApiResponse<FarmerProfileView>

--- PATCH /farmer-profiles/me/phone ---
Mô tả   : Cập nhật số điện thoại
Auth    : ROLE_FARMER
Body    : { "phone": "string" }   // 10 chữ số
Response: ApiResponse<FarmerProfileView>

--- PATCH /farmer-profiles/me/avatar ---
Mô tả   : Cập nhật avatar URL (upload file qua file-service trước)
Auth    : ROLE_FARMER
Body    : { "url": "string" }
Response: ApiResponse<FarmerProfileView>

--- PATCH /farmer-profiles/me/address ---
Mô tả   : Cập nhật địa chỉ
Auth    : ROLE_FARMER
Body    : AddressUpdateRequest { provinceId, communeId, addressDetail }
Response: ApiResponse<FarmerProfileView>

--- GET /farmer-profiles/users/{userId} ---
Mô tả   : Lấy profile công khai theo userId
Auth    : Public (theo SecurityConfig)
Path    : userId (UUID)
Response: ApiResponse<FarmerProfilePublicView>

--- GET /farmer-profiles/{id} ---
Mô tả   : Lấy profile công khai theo profile ID
Auth    : Public
Path    : id (UUID)
Response: ApiResponse<FarmerProfilePublicView>

GHI CHÚ
================================================================================
- GET /brand-profiles/me/access: ROLE_BRAND hoặc ROLE_BRAND_PENDING.
  Response: ApiResponse<{ active, canEditProfile, canSubmitDocuments }>.
- ROLE_BRAND_PENDING chỉ được thao tác hồ sơ/giấy tờ của mình theo trạng thái xét duyệt.
  REJECTED/LOCKED/DISABLED/DELETED chỉ được xem; API nghiệp vụ trả 403 BRAND_ACCESS_DENIED.
  ROLE_BRAND cũng bị kiểm tra trạng thái hiện tại, kể cả khi token chưa hết hạn.
- Quy tắc trạng thái và cấu hình triển khai: docs/brand-access.md.
- Upload avatar/logo/banner: upload qua file-service trước, sau đó PATCH URL tương ứng.
- Internal API dùng JWT ROLE_INTERNAL hoặc X-API-KEY (tùy cấu hình service caller).
- API Gateway strip header X-API-KEY khi route từ client.
